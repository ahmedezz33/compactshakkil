# محرّكُ Qwen على السينولوجي (Ollama)

محرّكٌ محلّيٌّ مستقلٌّ عن الـPC، يخدمُ الطبقةَ الدلاليّةَ لـCompactShakkil (ومشروعَ سادن).
بلا GPU → بطيءٌ على المعالج، لكنّه يكفي للاستدعاءاتِ النادرة.

## المتطلّبات
- سينولوجي **x86‑64** (Intel/AMD) — معمارية ARM لا يدعمُها Ollama جيّدًا.
- **ذاكرة**: qwen2.5:3b ≈ ٣–٤GB · 1.5b ≈ ٢GB · 7b ≈ ٦–٨GB. اترِكْ هامشًا للنظام.
  ابدأْ بـ**3b** (توازنُ دقّةٍ/ذاكرة لمهمّةِ «اختيار وجهٍ واحد»).
- Container Manager مُثبَّت.

## النشر
1. Container Manager → Project → Create → اسمٌ `ollama` → مجلّدٌ على السينولوجي → الصقْ `docker-compose.yml`.
2. شغّلْه. أوّلُ إقلاعٍ ينشئُ مجلّدَ `models`.
3. اسحبِ النموذجَ (Container Manager → Container → ollama → Terminal، أو عبرَ SSH):
   `ollama pull qwen2.5:3b`
4. اختبارٌ من الـPC على الشبكةِ المحليّة:
   `curl http://NAS_IP:11434/api/tags`  (يُفترَضُ أن يُظهِرَ النموذج)

## ربطُ CompactShakkil به
- في جذرِ المشروع، عدّلْ `semantic_config.json`:
  `"endpoint": "http://NAS_IP:11434/v1/chat/completions"` و `"model": "qwen2.5:3b"` و `"timeout": 60`.
  (قالبٌ جاهز: `semantic_config.synology.example.json`.)
- قِسْ قبلَ الوصل: `.\measure_semantic.bat` و`.\measure_semantic_gen.bat` — يستدعيانِ السينولوجي الآن.
  فعّلِ الطبقةَ فقط إن كان الصافي موجبًا (مبدأُ المشروع).

## أمان
- **لا تُمرِّرْ 11434 من الراوترِ للإنترنت** — محلّيٌّ فقط.
- جدارُ السينولوجي: اقصُرْ 11434 على عناوينِ شبكتِك المحليّة.

## سادن
نفسُ الحاويةِ تخدمُ «مدقّقَ إصداراتِ المواصفاتِ الأسبوعيَّ» — وجّهْه إلى `http://NAS_IP:11434`.
